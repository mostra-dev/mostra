## Found while building

- **shadcn's raw registry items aren't what `shadcn add` writes.** They carry an icon placeholder and style markers its CLI rewrites, so the kit vendors the CLI's own output for both styles instead of emulating it. Installing those raw items by URL with `mostra add` keeps them unrewritten: filed as #219, for the package that next touches packs.
- **Tailwind's preflight overrode a theme's heading rules** written under `:where()`; the theme's base rules are plain selectors inside `@layer base`.
- **A theme's portaled menus rendered transparent** in the first prototype, because its attributes were on a wrapper and portals render outside it; the build puts `data-theme` on `<html>`.
- **The kit's dark variant missed the root itself**, so a layer's `:root { @variant dark { … } }` never applied; it covers the root now.
- **The TanStack Table rule flagged version 9's own `createColumnHelper`**, found by the Skill's code samples; it flags it only beside version 8's names.
- **Arcata's choices vanished on a page without sections** (white on white), found in the final review screens; they are a field of colour on any ground.
- **The kit's registry test read `@mostra/react`'s built types**, which CI's unit job doesn't build: the kit's tests now depend on its dependencies' builds, as an artifact's type check reads them.
- **The plugin manifest's new `themes` key was strict**, which the schema check refuses within a revision (an older release accepted any value with a warning): it is read leniently, each malformed entry a warning.
- **A plugin theme's face never reached its page**, found by the end-to-end test of a plugin theme written at the closeout (until then plugin themes were checked at install and in the stack's unit tests): the stylesheet named the face `mostra-fixture-theme/fonts/…`, which Tailwind, inlining the theme's stylesheet, took as relative to it, so the page asked for a file that wasn't there; a scoped package (Studio's `@mostra/themes`) was left alone, which is why no built-in theme showed it. Every face is now named `@mostra:face/<package>/<file>`, which the build maps into its own packages (D181 item 4). `plugins.test.ts` "a theme a plugin carries" installs a plugin with a layer and a face of its own, finds it in `theme/list`, publishes a page in `["studio", "harbor"]` and finds the layer's colour, its face's file byte for byte and Studio's faces in the version; a seed red, then green.
- **By my own diff review:** `mostra verify --fix` resolved a fix's file by its path only, so a link inside the artifact could carry a write outside it; it now writes only files whose real path is inside the artifact's (`fix.test.ts`, a seed red, then green).

## Deviations

- **Studio is opinionated, not quiet.** D141 item 1 and D171 item 3 had it quiet; D181 (M86) makes it the editorial direction, with Arcata beside it, and keeps every value overridable (D68).
- **The questionnaire is built on native inputs, not shadcn's Questionnaire primitive** (ROUND-3 §1.4). The primitive submits its own form and keeps its steps' state itself, which clashes with the trusted Submit and with answers that live in fields; native radios, checkboxes and inputs work in either base and bind through `useField` (D181 item 10).
- **The Skill's `assets/studio.css` and its examples' copies are gone** (D162 item 1). A theme is built into each version from the manifest's stack, so no stylesheet is copied (D181 item 2); `tailwindStylesheet` stays exported, deprecated.
- **The kit vendors shadcn's CLI output, not its registry's JSON.** The raw items carry an icon placeholder and style markers the CLI rewrites on install, so the kit pins what `shadcn add` writes for both styles (`upstream/shadcn/`, README there), and #219 covers raw items by URL.
- **The shell and the server's own pages wear `frame`, not Studio** (D181 item 8, amending D171 item 2), and a page follows its frame's light or dark (D181 item 9).
- **`mostra add <name>`** routes a bare name that is a kit item to the kit, asking the instance which names those are (`pack/kit`, additive); any other stays an npm package (D181 items 7 and 13).
- **Ledger migration 19 is this package's** (field options); WP-34's planned migration is 20 (DATA_MODEL, ORGANIZATION-HOMES, WP-34's specification).
- **Size budgets** raised for `@mostra/protocol` and `@mostra/react` (D181 item 12); `@mostra/kit`'s modules have budgets of their own.
- **CI's groups** were rebalanced for the kit suite and the theme every build now carries (REPO_STANDARDS §6), and the conformance kit has a Windows group of its own (#225).
