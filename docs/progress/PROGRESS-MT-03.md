  1. (P1) A pause, or a revoked link, while the operator answered was not judged again: the run or call was recorded and relayed. Both are now checked after every wait, in the same synchronous stretch as the record or the relay.
  2. (P2) Idle expiry counted only frame loads, so a page open and in use past the idle time lost its link at its next ticket. Its other sessions' activity now counts too, the asking session left out.
  3. (P2) `bytes.held` never said 0 for a home emptied around a restart (its memory lived in the process). The level is now a running total in the directory, kept by triggers, with a dirty mark, so a change before a stop is reported after it.
  4. (P3) Refusals after the wait (the owner gone, the queue full) kept the link's use. One catch from the use to the record now gives it back.
  5. (P3) Nothing checked a refused call's give-back. The test now sends three refused calls before an allowed one, with a seed.
  6. (P3) Concurrent requests of one run each asked the operator. A duplicate now waits for the request on its way and joins what it recorded.
  7. (P3) A call the page abandoned during the wait still reached the owner. It is refused (`MOSTRA_ACTION_CANCELLED`) and never relayed.
  8. (P3) `__proto__` was a valid claim name and would set the facts' prototype. The schema refuses `__proto__`, `constructor` and `prototype`, and each claim is defined as a key of its own.
  9. (P3) The verifier backfill could label a typed-name identity whose provider ID later became a real provider's, and labels took control and format characters (a reversed "GitHub"). The backfill skips rows of another kind's shape; labels with control, format or separator characters are no verifier.
  10. (P3) `heldBytes` grouped the whole table every minute and every batch held a counter per home. Levels are now read from one row per home and sent when they change, with a daily snapshot, in batches of at most 1,000; a file missing at the backfill takes 0, so it is read once.

## Deviations

- **Idle expiry** is judged from the link's last use before the visit (its last view, and its other sessions' activity) rather than either of the two ways the request suggested (at the session exchange, or leaving the asking session out); both leave an idle link open to a returning browser (D169 item 3).
- **`bytes.held`** is sent when a home's level changes, and for every home once a day, rather than in every window as the request put it: the Opus review's finding 10 (a counter per home every minute).
- **The verifier** is recorded at every sign-in through the identity, not only when it is first linked, so a relabelled provider reaches its people's names at their next sign-in (D169 item 6).
- **The specification's request numbering** skips 8 (the hosted header's phone layout, which belongs to the design pass on the hosted surfaces).
