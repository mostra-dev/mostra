## What was built

- **The `identity` port** (D143 items 1 and 2): `port/identity.resolve` in `@mostra/protocol` (with `MOSTRA_HOST_IDENTITY_UNAVAILABLE`), asked by the gateway when a browser exchanges a link minted without a viewer; the answer is a viewer of kind `host`, recorded on the session (migration 10, `session.viewer_id`) and inherited by the frame's session. A host that took identity over and can't answer refuses the link (503) rather than letting a session act as someone else. The SDK serves it (`ports.identity`); the shell explains the refusal. `addressing` moves to WP-13 (HO-10), `reviews` and `capture` to WP-20 (HO-11).
- **Method metadata in the schema bundles**: `x-mostra-methods` and `x-mostra-notifications` (direction, mutating, params and result definitions) in both published bundles, kept additive by the compatibility gate.
- **`mostra-host`** (HO-03): wire types generated by typify 0.8.0 from the draft-07 bundle (`crates/mostra-host-codegen`, with a snapshot test and a gate that fails on any keyword, format or reference outside the checked subset; every enum opened with an `Unknown` variant), a typed method table, a tokio JSON-RPC client (one ordered writer, requests enqueued when called, notifications, port requests answered in their own tasks), `Mostra::spawn` and `Mostra::attach` (instance.json, the socket, a daemon started when none runs), port traits for `identity`, `submissions`, `drafts`, `trustedControls` and `secrets`, a named event stream with the SDK's guarantees, and the bundle manager (runtime resolution as the SDK's; pinned download through the caller's proxies and mirror, size and SHA-256 before extraction, strict extraction, every file against `files.json`, a digest-keyed cache with a lock, setup through the bundle's own `bin/mostra-setup`). It embeds its release's pins (`build.rs`; pins of another version are refused).
- **`@mostra/conformance`** (HO-05): the harness protocol, the runner (fresh home, runtime directory and shim per scenario, 240 s limit), baselines, the viewer the kit plays (cookie jar, link exchange, frame entry, fields, both submit channels, signals, runs, polls), 24 scenarios, the CLI (`mostra-conformance`), `serveHarness`, and the TypeScript reference host (`--standalone`, `--break`).
- **`mostra-host-reference`**: the Rust reference host, spawning or attaching, with every port and the same `--standalone` and `--break` modes.
- **HO-06 as a gate**: `tools/audit/host-neutral.ts` in the `boundaries` job, and JCODE_HOST.md's map from every need H-01 to H-16 to the scenarios that exercise it, kept true by a test. Three host names in core comments and CLI help were replaced.
- **CI and release**: a `conformance` job (the Rust reference host in its three modes, macOS and Linux); the kit's TypeScript runs in the `clients` integration group; the release rehearses the version its pending changesets make (`tools/release/versions.ts`), keeps the crate on the group's version (repo lint), packages the crate with the release's pins, and publishes it from the release's tag through crates.io trusted publishing (`tools/release/crates.ts`); `tools/release/crates-setup.sh` is the one-time first publish with Mirza's token.
- **Docs**: D143 (with M31), INTERFACES §17 (new) and §7, REPO_STANDARDS §2, §3 and §6, ARCHITECTURE §11, JCODE_HOST's scenario column, REQUIREMENTS (HO-01 narrowed, HO-10 and HO-11), the WP-13 and WP-20 specifications, VERIFIED_FACTS (WP-12), `docs/agents/release.md`, AGENTS.md and README.md of the crate, the reference host and the kit, the runtime's and the protocol's AGENTS.md, the root AGENTS.md's invariant owners; changesets for the protocol, runtime, SDK, shell, CLI and the new kit.

## Decisions taken in the package

Mirza delegated all seven questions at M31; the session's choices are **D143**, items 1 to 9. Choices made while building, under that delegation:
- **Timestamps stay strings** in the Rust wire types (typify would make them `chrono` values): a host stores and compares what the wire carries, and the crate doesn't impose a time library.
- **A delivery carries its raw JSON** beside the typed envelope, so a host that stores the submission opaquely (H-01) keeps fields a newer Mostra adds.
- **`close(&self)`**, and the writer ends when the session closes (found by the Rust reference host: a closed session kept the instance's stdin open, so every spawned instance waited 10 s for SIGTERM).
- **The release-age cooldown for crates by hand** (Cargo has no setting): nine young crates held back, the one security fix (rustls-webpki 0.103.16, RUSTSEC-2026-0382) kept.
- **The replay scenario opens its views while the host is there**: a host that serves identity refuses new links while it is away, by D143 item 2, so a view opened after it left can't exist.
