## Decisions

- **M81** (2026-11-18T15:27:44Z): Mirza started the unit with the assignment prompt and its specification.
- **M82** (2026-11-18T16:00:16Z): the session's questions (`prompt=consent` beside `login`, RP-Initiated Logout's parameter names, exact return addresses, a page's next sign-in asking again, the sweep's scope, the operator's one-click sign-out) delegated: "I trust you to make the most robust … optimal decision"; the operating layer's side of the unit permitted in this session.
- **D177** (proposed, brought with the candidate): signing out of the API origin, an operator's own app signing a person out of both, `prompt=login` and `prompt=consent`, a hosted page's sign-out, the sweep, and the metering window. Two deviations from the specification, each recorded there: return addresses are only exactly registered ones (RP-Initiated Logout §3), and `prompt=consent` is implemented beside `login` (the MCP SDKs send it with every request for `offline_access`).
- **A finding that changed the operator's one-click design** (D177 item 2): a form the app's own endpoint passes on to `/signout` with a 307 arrives with `Origin: null` in Chromium and WebKit (Firefox keeps the app's origin), so the app's form posts straight to the server, with a `state` the app checks when the person comes back (VERIFIED_FACTS, MT-06).
