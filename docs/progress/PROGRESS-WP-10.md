## Decisions taken in the package

Mirza set the consent model at M27 and answered the session's nine questions and two findings at M28; both are recorded as **D140**, with pointers from D60, D119 and D133. Choices made while building, under D140:
- `--timeout` that runs out is the protocol's own `MOSTRA_HOST_TIMEOUT` (exit 4) rather than a new CLI code; `host` and `dev`, which run until Ctrl-C or their connection ends, refuse `--timeout` with `MOSTRA_CLI_USAGE`, and help lists exit 4 exactly where `--timeout` applies.
- `mostra dev` drives Vite with `server.watch: null`: the supervisor, which keeps the mirror, says which files changed (Vite's own watcher missed changes in the mirror and would walk the package layout). In dev only, the entry's `export const artifact` is unexported in place, because React Fast Refresh gives up on a module that exports anything but components. A page reports when it was served once its modules have run, and one served before the last change loads again: Vite's client drops an update that arrives before its modules accept updates (found by the `mostra add` test, about one run in two). Vite's pre-bundled dependencies stay in the session's root, never beside the shared warm set. A preview's field coverage is open, so nothing is orphaned in a preview.
- Test-only variables: `MOSTRA_TEST_FLUSH_INTERVAL_MS` (the flusher's one minute) and `MOSTRA_TEST_LOCALTIME` (the `/etc/localtime` candidate).

## Deviations

- **The protocol's size budget** rose from 44 kB to 46 kB (45.22 kB measured) for WP-10's methods and codes.
- **`--timeout` on `host` and `dev`** is refused (`MOSTRA_CLI_USAGE`) rather than accepted and ignored: both run until Ctrl-C or their connection ends (INTERFACES §9 says so).
- **A flaky test of another package, made robust without loosening it:** `@mostra/protocol`'s `LineSplitter` linear-time test, whose 500 ms bound failed under parallel load in WP-09's and this package's baselines, now takes the larger of 500 ms and 20 times one pass over the same 32 MiB measured beside it; a splitter that searches its buffer again per chunk still fails it (seeded: 1.2 s against 500 ms).
- **The protocol suite** (`protocol-suite.test.ts`) expects `dev/notify` among the instance's notifications, additively.

## Untested boundaries

- **No collector exists** (it ships with the managed service), so sending was proven against a loopback fake collector; the published build's endpoint is empty, which the binary's `no-collector` status shows.
- **The telemetry question at a real terminal** is tested in-process with the terminal flags and the answers injected (`y`, Enter, `n`, end of input, Ctrl-C, 60 s); the contract suites run without a terminal, where it is never asked.
- **Harness markers** come from each agent's documentation or source (VERIFIED_FACTS, WP-10), and Mirza observed `CLAUDECODE=1` and `AI_AGENT` in Claude Code; the other agents weren't run here.
- **The login service on Linux**: the contract suites write the unit with `--no-start`; the real service manager was exercised only with launchd on this Mac (external, above). CI's Linux leg covers everything else.
- **`mostra open --browser`** is proven with a stand-in `BROWSER` that records its arguments; no real browser was started by the CLI.
- **`mostra dev`** is proven in Chromium; a page of a `pages/` artifact that lazily loads a route while an update arrives could miss that update until its next edit (the catch-up covers the entry's module graph).
- **The SDK-spawned telemetry case** is WP-11's, on the same test.
