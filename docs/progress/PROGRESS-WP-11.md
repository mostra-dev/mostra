## What was built

- **The runtime bundle** (`@mostra/bundle`, private; D142 items 1 to 3): `packages/bundle/scripts/build.ts` assembles `mostra-<version>-<platform>.tar.gz` for `darwin-arm64`, `darwin-x64`, `linux-x64` and `linux-arm64`, each on its own platform's runner: the official Node.js 24.21.0 (archives pinned by SHA-256 in `node.json`, from the signed `SHASUMS256.txt`), Mostra's packages deployed hoisted beside each other with pnpm 10 and that platform's native modules, the warm set deployed isolated, POSIX launchers in `bin/`, `LICENSE` and `NOTICE`, `files.json` (every file's size, SHA-256 and execute bit, every link) and `bundle.json` (`BundleInfo`, with the verify browser's pin). It refuses a link leaving the bundle, a file with more than one link, and any file naming the build machine's paths (an upstream file is exempt only when byte-identical to that package's published copy). The archive is a sorted, owner-free gzip tar with one fixed time. About 199 MB (782 MB unpacked, 49,476 files) on darwin-arm64.
- **The verify browser is fetched, never redistributed** (D142 item 2, amending ARCHITECTURE §4 and REPO_STANDARDS §9): Chrome Headless Shell is Google's binary under Google's terms, so the bundle pins it (revision, version, every file's SHA-256) and setup installs it with the bundle's own Playwright and checks every file.
- **`@mostra/protocol`:** the bundle contract (`BundleInfo`, `BundleFiles`, `BundleBrowser`, `BundleAsset`, `BundlePins`, `BundleSetup`, `BUNDLE_PLATFORMS`, `bundleAssetName`, `BUNDLE_SETUP_MARKER`) and four ENV codes: `MOSTRA_ENV_BUNDLE_INVALID`, `MOSTRA_ENV_BUNDLE_DOWNLOAD_FAILED`, `MOSTRA_ENV_BUNDLE_UNAVAILABLE`, `MOSTRA_ENV_NODE_UNSUPPORTED`.
- **`@mostra/sdk`** (new; D142 items 3 to 5 and 8): the bundle manager (`installPinned`: download through the caller's proxy, with a mirror's credentials as Basic authorization, bounded by the pinned size, hashed as it streams, three attempts; strict extraction; a digest-keyed cache with one locked installer per digest, scratch then rename; `setupBundle`, `checkFiles`, `checkBrowser`; `bin/mostra-setup`), the one runtime resolution (`resolveRuntime`), the platform gate (macOS and glibc Linux, arm64 and x64), and `createMostra({ home, ports, … })`: the host's own instance on the bundle's Node.js, ports checked against their schemas both ways, `publish`, `verify`, `wait` (abortable), `results`, `getState`, `patchState`, `pushLive`, `viewUrl`, `events()` (ordered, bounded, acknowledged per page for a named stream), `call` and `close`.
- **`@mostra/cli`:** runs on the runtime the SDK resolves; `doctor` checks the bundle (`--deep` re-hashes every file); the npm-installed copy is a bootstrap that installs its release's pinned bundle and runs the bundle's `mostra` with the same arguments, exit code and signals (`src/bootstrap.ts`), behind a gate that refuses a Node.js older than 22.19 before anything loads (`src/node-gate.ts`).
- **`create-mostra`** (new): `npm create mostra [dir]` runs that CLI's `mostra new` and prints the next steps.
- **`@mostra/runtime`:** verify renders with the bundle's own browsers; artifact children (installs, workers) find the runtime's Node.js first on `PATH`; an untyped package's TS7016 no longer fails verify (found by the bundle smoke test).
- **Releases** (D142 items 7 and 9): one Changesets `fixed` group for every published core package (repo lint enforces it); `.github/workflows/release.yml` (four bundles built, license-audited and smoke-tested with no Node.js; every package packed and dry-run published; the npm path smoke-tested on Node.js 22 and refused on Node.js 20; on `main`, in the protected `release` environment, attestations, the draft GitHub release, npm trusted publishing of exactly the tested tarballs, then the release); scripts `pins.ts`, `publish-npm.ts` (with a preflight that decides every package's publish before any), `notes.ts`, `smoke.sh`, `npm-smoke.sh`, `npm-old-node.sh`; `tools/release/npm-setup.sh` for Mirza's one-time npm steps; the `release` environment (deploys only from `main`) and immutable releases, applied through `tools/github/settings.ts`; `docs/agents/release.md`.
- **The `ee/` boundary** (D142 item 10): dependency-cruiser's `core-never-imports-ee`; the license audit refuses a core closure reaching `ee/` and audits `ee/`'s third-party dependencies apart; the api gate's packing check (`tools/api/pack.ts`) refuses a tarball with anything of `ee/`; `license-audit --bundle` audits each assembled bundle.
- **Repository machinery:** an integration group `clients` for the CLI's, the SDK's and `create-mostra`'s suites; repo lint refuses a script of the release's publish job that imports anything but Node.js built-ins; `prove-seeds.ts --anchors` (in the `boundaries` job) fails when a seed can no longer be planted.

## Decisions taken in the package

Mirza delegated every WP-11 question at M30; the session's choices are **D142**, items 1 to 11. Choices made while building, under that delegation:
- **Deploys copy** (`package-import-method=copy`): on Linux pnpm imports packages as hard links into its store, which node-tar writes as hard-link entries the SDK's extractor refuses.
- **The `clients` integration group:** the client packages' suites first ran in `core`, beside the runtime's, and starved a WP-08 timing test on macOS's 3-CPU runners.
- **The publish preflight** asks npm itself (`npm publish --dry-run` per package) before the first real publish, so a refusal npm could predict never leaves half a release; the publish job's scripts use Node.js built-ins only (it has no installed packages and holds the publishing credentials), which repo lint checks.
- **A mirror's credentials** travel as Basic authorization (fetch refuses a URL that holds them), and every URL in a download's message is reduced to its printable form.
- **The bootstrap forwards SIGINT only without a terminal:** at a terminal Ctrl-C already reaches the bundle's `mostra` (one process group), and a second SIGINT would cut `mostra dev`'s graceful stop short.

## Deviations

- **The verify browser is fetched at setup, not packed in the bundle** (D142 item 2): ARCHITECTURE §4 and REPO_STANDARDS §9 are amended.
- **RT-01's "without Node.js" is proven twice** (D142 item 6): fresh runners with no Node.js on `PATH` run the extracted bundle; `npm create mostra` itself needs npm, so the npm path runs on an older Node.js line than the bundle's and every Mostra process runs on the bundle's.
- **`@mostra/protocol`'s size budget** rose from 46 kB to 48 kB for the bundle contract.
- **The publish preflight** replaces a version comparison of its own with npm's dry run, to keep the credentialed job free of installed packages.
- **The release order** (D142 item 9, amended after the Opus review): the GitHub release is published and checked before npm, not after, and a half-published version is finished from the release's tag and archives; the workflow now runs on pull requests touching any package.

- **Reproducibility across two builds** of one platform wasn't measured byte for byte; the archive's contents are pinned by `files.json` either way.
